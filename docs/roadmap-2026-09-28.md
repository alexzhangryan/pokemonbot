# How to make the agent good: survey, measurements, and a ranked plan

*2026-09-28, Claude Code. Written for whoever picks this project up next, including the
Cowork surface. Everything labelled MEASURED was run against this repository or this
account's own traces on the date above, and the source is named so it can be re-run.
Everything else is cited to a surveyed work.*

The agent is at ~1200 Elo, 46.6 GXE, having just moved from a stuck 47-50% to 56.7% over
30 ladder games (D99-D101). This document answers what it would take to make it genuinely
strong, and it revises two things this project believed.

---

## 1. Where the field actually is, and what that means for the target

| system | rating | method |
| --- | --- | --- |
| Laplace | 2231 Elo (singles) | MCTS over 8 sampled opponent worlds in poke-engine, 368-feature value net used only near ties |
| foul-play | ~1930 Gen9OU | Monte-Carlo search over poke-engine, hand-tuned eval, usage-stats opponent sampler |
| **PokaiTrainer** | 1350-1400, peak 1492, **GXE 72-74** | CFR over belief states, exact Rust enumeration, per-world value net. **VGC doubles, same regulation lineage.** Plays with Open Team Sheets *accepted*. |
| philmantatsky / antonius1 | ~1365 peak | **This exact Champions Reg M-B doubles format.** Bundled Champions simulator for exact payoff, plus a behaviour-cloned policy. |

Two conclusions, and the second is a correction to what this project has assumed.

**Nothing strong uses an analytic payoff model.** Every system above gets its payoff from
an engine that enumerates or samples real outcomes, and uses learning only for the leaf
value and for proposing action menus.

**"Good" on this format means about 1400, not 1500+.** Nothing published in Champions or
VGC doubles is above ~1400, and PokaiTrainer reaches it with an exact Rust engine, CFR, a
per-world value net, ~250 L40S-hours of self-play, *and* open team sheets, which we
decline by design. The gap to the state of the art is one to two hundred Elo, not a
thousand. That is good news about tractability and bad news about ambition.

Compute is not the ceiling: PokaiTrainer's entire run was a few hundred dollars.

## 2. What the literature rules out

Each of these is measured against, not merely argued against.

- **Pure LLM agents in the decision loop.** The PokeAgent Challenge retrospective is
  unambiguous that all top finishers used RL or search. PokeChamp loses about a third of
  its games to *timeout* even at 150s+15s per turn, which is disqualifying under
  Showdown's VGC Timer, and it breaks the determinism requirement.
- **More particles.** Already measured null here (64 to 1024: coverage 96.4%, whole-set
  6.8% to 5.0%) and now *explained* -- see section 4.
- **More rows or columns.** Measured twice independently: six width changes here failed to
  move a stuck 47-50%, and PokaiTrainer's own ablation scored widened 24x24 interior menus
  at 42.6% against their native shape.
- **A learned policy that plays the game.** PokaiTrainer's *depth-one* search beats every
  policy head they trained (71% pooled), and their policy alone loses to a shallow
  material heuristic. The candidate prior already fitted here (recall@5 0.895 against the
  heuristic's 0.740) is the correct use of imitation: ordering candidates, not choosing
  moves.
- **Metamon-scale offline RL.** It needed 475k human battles and 38M timesteps.
- **Monte Carlo rollouts for payoff.** PokaiTrainer measured, on this game: capped
  enumeration of a joint action's outcome distribution costs **1.0 ms at 0.7%
  total-variation error**, while 256 Showdown replays of the same turn cost **509 ms at
  2.8%**. Enumeration is ~500x cheaper *and* more accurate. "Analytic model versus
  rollouts" was a false choice, and rollouts are the worst of the three options.
- **A public belief state formulation as the target.** Well-defined for this game in
  principle, and proven by PokaiTrainer, but not representable under *declined* Open Team
  Sheets, because the value-net input grows with the number of infostates in a public
  state.
- **The academic VGC AI Competition.** Despite the name it simulates randomly generated
  creatures in *singles* with its own engine. Read it for framing; do not build against
  it.

## 3. The structural error: a value is a vector, not a number

Every paper in the imperfect-information family says this in different notation --
DeepStack's per-hand counterfactual values, Brown and Sandholm's Proposition 1, ReBeL's
per-infostate vector, SoG's CVPN, PokaiTrainer's per-world value head. **In an
imperfect-information game a position's value is indexed by the opponent's private
information.**

This project collapses that vector twice. The payoff layer averages over the 64 belief
particles *inside* each cell, and then one matrix game is solved -- which forces the
opponent to play a single strategy that does not depend on their own team. That is the
wrong game. The right object is one row strategy for us and one column strategy *per
world* for them.

This also reframes D97. Adding a second ply on top of an inexact payoff model over a
collapsed value is expected to lose, so D97 probably measured the wrong thing, and
`docs/engine-gate.md` inherits the same doubt: its own Limits section records that the
oracle arms knew the opponent's six sets *but not the bring*, and redrew unrevealed
brought slots at random per decision. The fidelity question has never been measured
cleanly in either direction.

## 4. The belief filter: the defect, and a correction to the correction

**MEASURED.** `champions/belief/particles.py`, three soft-evidence handlers
(`_apply_speed` ~576-591, `_apply_incoming` ~687-690, `_apply_outgoing` ~779-782) all have
this shape:

```python
allowed = [points for points in spread.feasible_points("spe") if _speed_consistent(...)]
if not allowed:
    particle.log_weight += math.log(SOFT_INCONSISTENT)   # the ONLY reweighting path
    continue
if not spread.restrict_points("spe", allowed):
    particle.log_weight += math.log(SOFT_INCONSISTENT)
```

If *any* point value is consistent, the weight is unchanged. Every speed and damage
observation is therefore a **0/1 feasibility test, not a likelihood** -- an indicator where
there should be an integral over the nuisance parameter. There is no
`log P(observation | particle)` term anywhere. So the nature marginal is identically the
prior, and "60.9% on turn 1, 60.8% on turn 11" is the prior's accuracy printed twice. It
also explains the particle-count null: a population with no weight gradient cannot prefer
the truth it already contains.

Corroborating, from 3,642 live belief snapshots: the opponent's stat-point box is **fully
vacuous, `[0,32]` on all six stats, 72.2% of the time**, its lower bounds total **1.7 of
the 66-point budget**, and it narrows only from width 32.00 to 30.26 over nine turns.
Since `spreads.allocation()` then spends the budget by a heuristic keyed on the guessed
nature, the opponent stats that price every damage cell are in effect a deterministic
function of one guessed categorical variable.

**The correction.** A reviewing agent argued this fix is provably inert: `feasible_points`
returns a contiguous run and the consistency test is monotone, so `allowed` is a sub-run,
the hull changes if and only if the set shrinks, and it claimed shrinkage happens 0.06% of
the time -- making `log(mass(allowed) / mass(feasible))` equal to `log 1 = 0` almost
always. The structural half of that is right. The frequency is wrong.

**MEASURED**, instrumenting `restrict_points` over 20 open-sheet replays, 23,779 calls:

| quantity | value |
| --- | --- |
| calls that narrowed the candidate set | **43.07%** |
| mean ratio of allowed to feasible | 0.788 |
| on the 43% that narrow, mean ratio | 0.508 |
| mean log-weight the missing term would add, on those | **-0.997** |

So the missing multiplication would carry real information -- a factor of about 0.37 on
43% of observations -- and it is roughly five lines at each of three sites. The reviewer's
objection does not hold. Caveat: this was measured in the corpus harness, which feeds the
filter a neutral own-side spread; if anything that makes the test *less* discriminative
than it would be live, where our own stats are exact.

Two further pieces belong with it.

- **Exact roll-mass damage likelihood.** `_damage_consistent` is an interval-overlap test
  against only the 85 and 100 rolls, under `DAMAGE_TOLERANCE = 0.05` and
  `UNCERTAIN_TOLERANCE = 0.40`. Replace it with a sum over the 16 rolls of
  `P(roll) * 1[quantise(damage) == observed bin]`. That is exact, correctly normalised and
  automatically soft, and it *deletes* the tolerance constants rather than tuning them.
  Roll spread is 15% of the damage while HP quantisation is under 1 HP of a ~175 maximum,
  so roll randomness dominates quantisation by more than an order of magnitude. This is
  what makes the test discriminative rather than merely present.
- **A sufficient statistic instead of a bounded replay.** `resample()` discards the
  population, redraws from the constrained prior with every box back to `[0,32]`, and
  replays at most 48 soft evidences -- about 4.1 resamples per game against a 7.0-turn
  mean, so a sharp posterior is repeatedly reset. Accumulate a per-(species, hypothesis)
  log-likelihood instead, which never forgets and makes resampling harmless.

**Not** an amortised neural posterior: **MEASURED**, 0 of 17,028 corpus sets carry stat
points, so the one inert field cannot be supervised at all.

## 5. Six things nobody had looked at, all measured today

1. **The switch columns are unpriced and about half fictional.** `_annotate_unseen` writes
   every previewed-but-unseen opponent Pokemon onto the bench so switch columns exist
   (D91). **MEASURED**, 5,416 non-lead preview slots in regmc replays with the bring fully
   observed: `P(brought | previewed, not a lead) = 0.491`. And **MEASURED**, 1,028 switch
   columns in live traces carry **no `prior_weight` at all**, so `_per_column_prior` falls
   through to an even split of their kind's rate. On turn 1 the revealed bench is empty, so
   *every* switch column the minimax defends against is an action about 49% likely to be
   legal, priced as certain. This is D101's own recorded lesson unapplied to the one column
   class D100 did not price -- and measured luck is -8.1 on turn 1 and -7.5 on turn 2,
   decaying to zero by turn 7, exactly the schedule on which the unseen fraction of the
   bench decays.
2. **The ladder has no adaptive adversary.** **MEASURED**, 328 rated games: 323 distinct
   opponents, 10 games (3.0%) against anyone seen twice, never three times, no Bo3. A mixed
   strategy has almost no defensive value here, so sampling a mixture is close to a pure EV
   concession.
3. **The agent wins short games and loses long ones.** **MEASURED**: wins mean 5.63 turns
   (n=159), losses 7.13 (n=167), difference +1.50 turns, SE 0.28, **z = 5.4**. A game ends
   symmetrically when either side loses four Pokemon, so there is no structural reason for
   this. Win probability declines in turn number: the agent has no multi-turn plan. Nobody
   had computed this and it is free from the ledger.
4. **The mixed strategy is not recorded.** The trace keeps the entire 64-particle posterior
   every turn and lists `mixed_strategy` and `game_value` as `pending`. So "what does mixing
   cost us" cannot be measured from 328 games of history. One line in the trace writer.
5. **Every fitted prior has a distribution shift nobody stratified.** **MEASURED**: regmc
   replays by Bo3 position are 419 / 361 / 165, so **56% are games 2 or 3** -- informed
   re-picks against a team already fought -- and **all 945 have open sheets**. The ladder is
   100% game 1 of a Bo1 with sheets declined. The `game_number` column is already in the
   schema.
6. **The preview sweep dominates the harness.** **MEASURED**, 160 agent-games: preview
   14.34 s against 1.72 s of all in-battle decision time, so preview is **89.3% of the
   agent's compute**, and in self-play both sides pay sequentially. That is ~29 s of a ~50 s
   battle, so removing it is worth roughly **2.4x throughput**. (A reviewing agent claimed
   8-10x by assuming the non-preview remainder was 4.1 s; measured here it is ~21 s, most of
   it simulator and protocol.) This matters because D71 says a 5-point gap needs ~1,500
   games an arm, and every gate anyone proposed was specified at 200-400.

## 6. The deepest point: the opponent is not adversarial

Every measured failure in this project's log is one failure. D99 shipped a strictly more
accurate belief and lost 35-55 because the extra columns arrived unpriced and minimax
converted them into pessimism. D100 found the mechanism: one column the belief weighted at
2% took the solve from 0.532 to 0.237. The free adversary wants 30-68% Protect mass against
a field that Protects 4-14%. Measured luck is worst on exactly the turns where the adversary
has the most columns. And section 5 adds that the turn-1 switch columns it hedges against
are about half fictional.

The architecture spends its budget buying robustness against a best-responder that the
ladder contains **3.0% of the time, never more than twice, and never in a Bo3**.

`PRIOR_WEIGHT` has been 0.8 by taste since D91, and has always been discussed as a knob to
retune. **`PRIOR_WEIGHT = 1.0` is not a knob position -- it is best response to the fitted
opponent model with minimax deleted**, and it is a one-line diff that has never been run. A
minimax solve is the right object for the Protect and Fake Out prediction interactions the
design document names. It is a tax everywhere else.

## 7. The plan, in the order that falsifies itself fastest

**Phase 0 -- days, zero research, every direction measured rather than hypothesised.**

| # | change | size | why now |
| --- | --- | --- | --- |
| 1 | Record `mixed_strategy` and `game_value` in the trace | 1 line | Nothing about mixing is measurable without it, and later gates need it |
| 2 | Price switch columns at `P(brought) = 0.491`, decaying to 0 once four opponent Pokemon have appeared | ~2 lines | Targets turns 1-2, where luck is -8.1 and -7.5 |
| 3 | A/B `PRIOR_WEIGHT` in {0.8, 1.0} | 1 line | Section 6; the ladder cannot punish best response at a 3% repeat rate |
| 4 | Measure the preview sweep's value, then shorten or delete it | 1 flag | ~2.4x throughput, the precondition for reading any later gate |

**Phase 1 -- one to two weeks. Make the belief actually learn.**

| # | change | why |
| --- | --- | --- |
| 5 | Add the box-particle likelihood term at all three handlers | 43.07% of observations carry information currently discarded |
| 6 | Exact roll-mass damage likelihood; delete the tolerance constants | Makes the test discriminative rather than merely present |
| 7 | Per-hypothesis accumulated log-likelihood instead of the 48-item replay | Stops the posterior being reset about four times a game |
| 8 | Condition the set prior on the six previewed species, which are public even with sheets declined | Reported +7.4pp whole-set and +4.4pp nature, held out by player, and it lands at turn 0 -- which matters because the mean game is 7.0 turns |

Gate Phase 1 on an **oracle-counterfactual replay** before any ladder games: re-solve every
logged decision twice, once with the belief as logged and once with the true teams in the
`SetSource` slot, and report mean per-decision regret in win-probability points. That is a
direct upper bound on everything downstream and it costs no games.

**Phase 2 -- weeks, and only if Phase 1's gate clears.**

| # | change | why |
| --- | --- | --- |
| 9 | Widen `SetSource` to `sample(n)` and take the belief-weighted matrix average | The *safe* 80% of the per-world game, about 20 lines. Do **not** start with the per-world minimax residual, which Jensen guarantees is one-directionally more pessimistic and which every judge identified as the hazard |
| 10 | Exact capped transition enumeration as the payoff layer, keeping the leaf learned | 1.0 ms at 0.7% total-variation error against the analytic model's unknown error; this is what every strong system does |
| 11 | A 1v1 matchup-matrix eval feature (Athena2020) | Non-zero at turn 1, which the current nine-feature eval never is, and the cheapest candidate fix for the length asymmetry in section 5 |

**Explicitly not on the plan:** more particles, more rows, more columns, a policy that
plays, an LLM in the decision loop, rollout-based payoff, a PBS value net, and any further
games of the current configuration.
